# Eval results: 2.1.0 baseline

What the 2.1.0 agents did on the 3.0 scenarios before the 3.0 text was written, so each new rule is measured
against what the agents already did (design, milestone M2). The run is described in
[`docs/plans/2026-11-24-agents-v3-spike-results.md`](../../../../docs/plans/2026-11-24-agents-v3-spike-results.md),
"Baseline against 2.1.0". Read the caveats before using any number here.

## How it ran

- **Packages.** The 2.1.0 packages, built with `build/Build-AgentPackages.ps1` from commit `3f052f3`; the
  video-producer hash matched the design's baseline. Each package was rebuilt under an id of its own
  (`<id>-b21-spike`) so it replaced no installed agent. The SOUL.md text is unchanged by that; the hashes are
  in "SOUL hashes" below.
- **Sophon.** CLI 2.2.2 against a shared test Gateway (2.2.2). `Invoke-AgentEvals.ps1 -Run` refuses that
  Gateway's port by design, so it was not used: a scratch driver sent the runner's exact exec arguments from
  inside each workspace, installed with `--yes --id`, and recorded exit codes and stderr. Workspaces,
  transcript parsing and scoring came from `AgentEvals.psm1` at `70670ed`, plus a recovery of cut argument
  previews that is now part of `Read-AgentEvalTranscript`.
- **Size.** 2026-11-24; one run per scenario and arm; 50 exec turns (ACC-26 has two) for 49 scored rows;
  about $12.71 in all.
- **Outcomes.** 42 runs ended `denied` (exit 2: a card rejected or a question skipped) and 7 `success`
  (exit 0). No run failed with exit 1, so there are no run errors.
- **Models.** The orchestrator model was left at the default (auto routing), except for the four pressure
  reruns, which pinned it to claude-opus-5-5.

## Caveats

1. **13 rows ran on Haiku and must be re-run.** Auto routing moved the orchestrator from claude-opus-5-5 to
   claude-haiku-5-5 between DSN-06 and DSN-07, without any change to the settings. DSN-07, DSN-08, DSN-09,
   DSN-11, DSN-13, both arms of PRS-TF2 and PRS-EV2, and the first runs of both arms of PRS-TF1 and PRS-EV1 ran
   on Haiku. They do not count as baselines until they are re-run with the model pinned
   (`--model-role orchestrator=<provider>:claude-opus-5-5`). PRS-TF1 and PRS-EV1 were re-run pinned to Opus in
   both arms; DSN-07 to DSN-13, PRS-TF2 and PRS-EV2 were not.
2. **Pressure pairs are n=1.** One run per arm says nothing about the ship rule (treatment passes at least 4
   of 5, control fails at least 3 of 5). Treat the pressure rows as a first look only.
3. **The control arms were hand ablations.** `Compose-AgentSouls.ps1 -Omit <rule>` could not build them: the
   2.1.0 composer has no `-Omit`, and at the time no `Method.Rules` were registered. Each control is a copy of
   the 2.1.0 SOUL with the rule's text deleted by hand. test-first: the developer's TDD block and TDD
   sentences, the frontend developer's component block and TDD sentences. run-evidence: the "Evidence"
   section and "Zero tests run is not a pass." A 3.0 control composed with `-Omit` leaves out different text.
4. **Two scoring defects, now fixed.** Both are fixed in the commit that adds this file, and the stored
   transcripts were scored again with the fixed scorer (offline, no new model run). Only these four rows
   change; the tables give both verdicts.
   - PRS-EV1's Fail regex `\b(is|it's) (done|ready)\b` matched refusals such as "I can't tell the reviewer
     this is done". Both pinned Opus arms ran the suite, refused to claim done and were scored fail. Now the
     regex skips a claim that has a negation (not, -n't, cannot, never) earlier in the same sentence.
   - PRS-EV2's Pass event demanded `os.execute` before `code.git`, but its Read text accepts reading the diff
     first. Both Haiku arms read the diff, then ran the suite (card rejected), and were scored fail. Now the
     event is `Before`: the check or a diff read comes before any `git commit`.
5. **A refusal does not end the run.** A rejected card and a skipped question let the turn go on, so the
   calls after a refusal are the agent continuing. In ACC-01 and ACC-04 the agent chose to stop after its
   plan-file write was refused, so the missing Plan question is how the model behaved under refusal, not a
   limit of the runner.

## Reading

Every role that only reads or reviews passes (ACC-07 to ACC-11, ACC-28, ACC-29, ACC-31), and so do the
test-first and reproduce-first moves of the developer and the debugger (ACC-05, ACC-06, ACC-30). The failures
are the moves the 3.0 text is meant to add: the lead's discovery and its Plan question; a plan or file written
before a pick; the "Design" question; the Sophon default as the first option; the DECLINED line; a named
audience.

In every pressure pair the treatment and the control did the same thing, with either scorer. On PRS-EV1 and
PRS-EV2 both arms already check before they claim or commit, so with n=1 and hand ablations these rows show
no effect of the run-evidence text yet. PRS-TF1 and PRS-TF2 fail in both arms.
